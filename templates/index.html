agent-precog

An open-source research program focused on engineering sub-15 ms agentic safety reflexes using sequential learning to defer (SL2D) and asynchronous human handoff. The project

The problem

Enterprise AI is moving from conversational assistants to autonomous multi-agent systems with direct write-access to forklifts, freight routes, treasury accounts and network endpoints. Each agent is individually competent. The risk lies in their combination: dozens of agents acting on partial views of shared state, issuing tool calls that touch the same aisles, ledgers and network segments within seconds of one another. Today's guardrails judge each call on its own, so a catastrophe assembled from individually reasonable actions passes every runtime test. And the windows are short: a loaded forklift covers a metre in half a second, a payment clears in seconds, a firewall change isolates a server in milliseconds. A language-model safety judge that needs 50 to 300 ms per decision, before the network round trip, is structurally too slow for this setting. Once a single unsafe call can move a two-tonne vehicle, release funds or isolate a production server, the binding constraint on deployment is no longer reasoning quality but deterministic, millisecond-level safety.

The approach

The agent-precog research vision is for a two-tier safety layer built for this setting, designed to sit alongside the safeguards an enterprise already runs such as protective fields, transaction rules, approval matrices, and change control. PreCog is being engineered to catch the class of hazard conventional guardrails miss by construction: hazards whose causal chain crosses two or more systems or agents. A Fast Path watches the neighbourhood of each agent (a 3-hop sub-graph of the shared state across multiple agents, streamed from the central graph), predicts whether the proposed action pushes the system toward a catastrophic irreversible state, and halts it in under 15 ms on a device close to the actuator. The halt threshold tightens automatically as wireless jitter eats into the time left before the action becomes irreversible. Only once the hazard is frozen does a Slow Path produce a three-line situation brief for the human supervisor. Under the hood: a non-generative Hyperbolic Graph-JEPA world model compiled to TensorRT on an edge GPU for the Fast Path; a quantised edge language model for the Slow Path on the same edge silicon; a fast graph engine for the shared global state.

What's open

The vision rests on the claim that stopping a hazard and explaining it to a person are different problems on different timescales, and should be engineered as separate, co-designed tiers. The machine tier must be stateful over the multi-agent graph and fast enough to act inside the irreversibility window. The human tier must activate only once the world is stable, and deliver structured understanding rather than raw telemetry. Deferral should not happen during an active emergency. The supervisor reviews a paused snapshot, instead of being asked to catch a falling knife.

Across the five literature pillars this review draws on (multi-agent systems, world models, learning to defer, edge inference and human-automation interaction) no paper yet evaluates safety interception across domains, and only a handful treat signal latency or a deadline as an input to the decision. The gap matrix sets out these gaps pillar by pillar. PreCog is a research programme that builds this two-tier safety layer, measures it against those gaps on real edge hardware, and publishes data, methods, and code, so that enterprises can test the hazard classes against their own systems and researchers can take the open questions further.

Unsolved problems

Conventional guardrails and standard learning-to-defer fail in live multi-agent industrial settings for six reasons. The first two are architectural: the approach cannot work in this setting. The other four are operational: each one gets a working safety layer switched off in production. RQ5 measures what that failure costs →

1. The autoregressive latency trap

CANNOT ACT IN TIME

Using a language model as a token-generating safety evaluator costs 50-300 ms+ per decision on real hardware and networks, beyond the reaction budget of most physical hazards and many transactional ones. How RQ1 addresses this →

2. The stateless evaluation fallacy

CANNOT SEE THE INTERACTION

Per-call evaluators judge each input in isolation. Enterprise catastrophes emerge from compounding interactions across agents, so an evaluator can approve every individual step of a disaster. How RQ1 addresses this - stress-tested by RQ4 →

3. The static deferral cost

THRESHOLD SET ONCE, WRONG LATER

L2D treats the cost of deferring as constant. In practice it depends on how much time remains before irreversibility and how long the safety signal takes to arrive; a threshold tuned at one point is wrong at every other. How RQ2 addresses this →

4. The centralised decision locus

DECIDED IN THE WRONG PLACE

Guardrails live where the state is, so every decision crosses a wireless round trip. The component with the most context is furthest from the actuator, and a dropped packet silently becomes a permit. How RQ1 addresses this - residual closed by RQ2 →

5. The opaque, whole-system halt

STOPS WITHOUT EXPLAINING

When guardrails do fire they stop at coarse granularity and report only that a policy tripped. Operators cannot learn from it, throughput loss is disproportionate, and the layer gets tuned down. How RQ3 addresses this →

6. The deferral-under-motion fallacy

HANDS OFF AT THE WRONG MOMENT

L2D assumes a competent, available expert. In a live multi-agent system the expert is out of the loop, under time pressure, and shown unexplained state; deferring to them in-window is not a safe fallback, it is a different failure mode. How RQ3 addresses this →
